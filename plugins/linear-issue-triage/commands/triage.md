# Triage new EkkoLLM issues

Triage newly created Linear issues for the EkkoLLM team only (team key EKK). Poll for recent issues and process each new issue once; do not modify old issues that predate this automation. Use the authenticated Linear MCP tools.

Automatically apply the best matching existing classification label only when clearly supported by the issue: Bug for defects/regressions; Feature for new capability requests; enhancement or Improvement for enhancements/refinements. Do not apply retired labels (frontend, needs-backend, tech-debt), and do not invent or create labels. Leave unrelated labels unchanged. If no label clearly fits, leave classification unchanged.

Leave priority unassigned (No priority); never set or change it. Do not assign an owner.

For every new issue, search existing EkkoLLM issues for likely duplicates and related work. If it is clearly a duplicate, link the new issue as a duplicate of the best matching existing issue (do not close or delete either issue). If it is related but not a duplicate, create a related-issue link. Do not force links on weak matches; avoid duplicate links to the same issue. Record a short, factual triage comment only when useful to explain decisions or matched links. Never alter descriptions or issue status. Avoid reprocessing the same issue on later polls; check current labels and existing relations/comments before taking actions, and only act when needed.
